## Розділ 2. Збір і аналіз вимог

**2.1. Обстеження предметної області та бізнес-процеси**
Об'єктом дослідження є процеси управління фондом та обслуговування користувачів у бібліотечній системі. Основними бізнес-процесами, що підлягають автоматизації, є:
* **Централізований облік**: ведення надійної бази даних книг та їх фізичних примірників.
* **Автоматизація обігу**: фіксація операцій видачі та повернення з миттєвим оновленням статусу наявності.
* **Проактивна комунікація**: автоматичне відстеження термінів повернення та надсилання нагадувань боржникам.

**2.2. Функціональні вимоги (FR)**
* **Реєстрація та автентифікація**: обов'язкова ідентифікація користувачів для доступу до системи.
* **Динамічний каталог**: перегляд бази книг із фільтрацією за жанрами та інтерактивним пошуку.
* **Резервування**: можливість онлайн-бронювання примірників з автоматичною перевіркою статусу.
* **Облік видачі**: розрахунок планової дати повернення (due_date) та зміна статусу примірника на "видано".
* **Моніторинг**: перегляд графіків обігу та формування звітності про прострочення для адміністратора.

**2.3. Нефункціональні вимоги (NFR)**
* **Архітектура**: використання трирівневої моделі (Presentation, Application, Data Layer) для масштабованості.
* **Продуктивність**: висока швидкість обробки запитів завдяки асинхронній природі Node.js.
* **Надійність**: цифрове зберігання даних, що усуває ризики втрати або пошкодження паперових карток.
* **Інтерфейс**: забезпечення сучасного та швидкого інтерфейсу на базі React.

**2.4. Обмеження та зовнішні умови**
* **Технології**: реалізація на базі Full Stack JavaScript (React/Node.js/PostgreSQL).
* **Інтеграція**: використання зовнішніх сервісів для відправки email-сповіщень.

* **Для безпечного керування параметрами підключення до бази даних та секретними ключами авторизації використовується файл змінних оточення**:

```env
DB_NAME=library_db
DB_USER=postgres
DB_PASSWORD=your_password
DB_HOST=localhost
DB_PORT=5432
SECRET_KEY=your_jwt_secret_key
```

* **Примітка**: Файл .env обов'язково має бути доданий до .gitignore, щоб уникнути витоку конфіденційних даних у публічний репозиторій.
