## Розділ 12. Вибір методології розробки

Для реалізації проєкту «Моделювання інформаційної системи автоматизації для бібліотеки» було обрано **гнучку методологію розробки Agile (фреймворк Scrum)**. Цей вибір обґрунтований складністю взаємозв'язків між модулями та необхідністю ітеративного тестування функціоналу.

### 12.1. Обґрунтування вибору Agile/Scrum
* **Ітеративний підхід**: Розробка була розділена на спринти (етапи), що дозволило спочатку реалізувати ядро системи (базу даних PostgreSQL та базовий API), а потім поступово додавати складні модулі, такі як `overdue-check` та візуалізацію статистики через `Chart.js`.
* **Адаптивність**: Гнучкість методології дозволила коригувати схему бази даних (наприклад, структуру таблиці `book_items`) без зупинки загального процесу розробки.
* **Фокус на якості**: Кожна ітерація завершувалася рефакторингом коду та тестуванням маршрутів через Postman, що забезпечило стабільну роботу Express-сервера.

### 12.2. Етапи розв'язання задачі (згідно з курсовою)
1. **Планування та аналіз**: Визначення сутностей (Книга, Користувач, Позика) та проектування ER-діаграми.
2. **Проєктування архітектури**: Вибір стеку React + Node.js та налаштування пулу з'єднань у `db.js`.
3. **Розробка (Development)**: Створення REST API та інтерфейсу адміністратора з використанням Axios для запитів.
4. **Тестування та відлагодження**: Перевірка логіки автентифікації через JWT та коректності розрахунку дати повернення книги.
